How should the whole app be composed?

Five pieces have to coexist: the 3D die(s), workload selector, precision bar chart, memory-flow animation, and the comparison table. The question is the meta-structure tying them together. Wireframes below — green = 3D, blue = charts/data, grey = controls.

Everything on one screen, cross-linked & live. Pick a workload → die lights up, table + chart update together. Best for "play with it." Densest.

B

Scrollytelling Narrative

① the die — what's on it
② pick a workload → watch it light up
③ precision collapse (L20 FP64)
④ memory bandwidth flow
⑤ compare ▾ ▾ ▾

Guided top-to-bottom story; each scroll section is one chapter of the thesis. Best for "teach me in order." Less free exploration.

C

Tabbed Workbench

card picker + workload (persistent header)
［ Die ］ Precision ｜ Memory ｜ Compare
active tab fills the stage
(here: 3D die)

Shared controls up top; one big view at a time via tabs. Each component gets full room, no clutter. Loses the "see everything react at once" payoff.

My lean: A (Explorer) — the brief's core payoff is "select a workload and watch blocks light up while the chart and table move." That cross-component reactivity lands hardest when it's all visible at once. B is more memorable for a first-time viewer but weaker as a tool an investor can poke at. Click your pick.
